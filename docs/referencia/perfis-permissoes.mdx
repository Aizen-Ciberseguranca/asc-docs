# Perfis e permissões

O acesso às funcionalidades do ASC depende do **perfil do usuário** e das permissões atribuídas pela organização.

Por esse motivo, dois usuários da mesma empresa podem visualizar módulos, projetos ou ações diferentes.

## Perfis de usuários do cliente

Os usuários de uma organização podem possuir os seguintes perfis:

| Perfil | Finalidade |
| --- | --- |
| **Admin cliente** | Administração dos usuários e dos recursos disponibilizados para a organização. |
| **Técnico cliente** | Utilização das funcionalidades operacionais liberadas para o usuário. |
| **Visualização** | Consulta das informações disponibilizadas, sem funções administrativas. |

## Admin cliente

O perfil **Admin cliente** possui as permissões administrativas disponibilizadas para a organização.

Entre suas responsabilidades podem estar:

- criar usuários;
- definir perfis;
- liberar acesso a projetos;
- liberar acesso a módulos;
- redefinir senhas;
- remover acessos;
- configurar permissões disponibilizadas pelos módulos.

As funcionalidades disponíveis também dependem dos módulos habilitados para a organização.

## Técnico cliente

O perfil **Técnico cliente** é destinado aos usuários que precisam trabalhar com as funcionalidades operacionais disponibilizadas pela plataforma.

O acesso efetivo depende dos projetos, módulos e permissões atribuídos ao usuário.

## Visualização

O perfil **Visualização** é destinado principalmente à consulta.

Esse perfil pode visualizar as informações às quais recebeu acesso, mas não possui as mesmas permissões administrativas do **Admin cliente**.

## Projetos

Além do perfil, o usuário precisa possuir acesso aos projetos correspondentes.

Um usuário pode visualizar somente os projetos que foram liberados para sua conta.

:::info Projeto

No ASC, um projeto também pode representar uma filial ou outro contexto utilizado pela organização.

:::

## Módulos

Os módulos são habilitados por projeto.

Os principais módulos do ASC são:

- **Intelligence**
- **Monitoring**
- **Compliance**

Um módulo somente fica disponível quando estiver habilitado no projeto e liberado para o usuário.

## Permissões no Intelligence

Para usuários de clientes, o **Intelligence** é utilizado para consulta das informações e exportação dos resultados disponíveis.

Algumas operações relacionadas à execução e administração das varreduras são realizadas pela equipe responsável pela operação do serviço.

Por isso, determinadas ações podem aparecer indisponíveis para usuários do cliente.

## Permissões no Monitoring

No **Monitoring**, as funcionalidades disponíveis podem variar conforme o perfil e as áreas liberadas para o usuário.

Isso pode afetar a disponibilidade de recursos como:

- Chamados;
- Relatórios;
- Inventário;
- Solicitação de regras;
- Firewall.

## Permissões no Compliance

O **Compliance** também pode apresentar diferentes níveis de acesso.

Dependendo das permissões atribuídas, o usuário poderá acessar diferentes áreas relacionadas aos assessments, dashboards, documentos, controles e relatórios.

Em alguns casos, o acesso pode ser limitado somente ao **Dashboard**.

## Por que um menu não aparece?

Quando uma opção descrita na documentação não estiver disponível, verifique:

1. se o projeto correto está selecionado;
2. se o módulo está habilitado no projeto;
3. se o usuário possui acesso ao projeto;
4. se o usuário possui acesso ao módulo;
5. se o perfil possui permissão para utilizar aquela funcionalidade.

Caso o acesso devesse estar disponível, entre em contato com o administrador da sua organização.

## Princípio de menor privilégio

Ao configurar usuários, recomenda-se conceder somente os acessos necessários para a função desempenhada.

Administradores devem revisar periodicamente:

- usuários ativos;
- perfis atribuídos;
- projetos liberados;
- módulos liberados;
- permissões adicionais.

Isso reduz acessos desnecessários e facilita a administração da plataforma.
